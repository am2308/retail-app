Why Prometheus + Grafana

The observability case — explained plainly

Observability = knowing why something broke, not just that it broke. The three pillars are Metrics, Traces, and Logs. This session covers Metrics.

🔬Why Prometheus
  • Pull model — Prometheus scrapes /metrics. Dead service = immediate alert.
  • Labels — slot=blue, slot=green baked in. Filter during cutover.
  • PromQL — exact p95/p99, not averages. Your SLAs need this.
  • Free — no per-host charges unlike Datadog.
  • K8s-native — ServiceMonitor CRDs auto-discover pods.
📊Why Grafana
  • 50+ data sources — Prometheus today, Loki logs + Tempo traces next.
  • Zero lock-in — same dashboards work self-hosted or AWS Managed.
  • Alerting — unified alert evaluation in Grafana 10+.
  • 100k dashboards — import community ones with one click.
  • LGTM stack — Grafana is the UI layer for the whole observability ecosystem.
☁️AWS Managed vs Self-Hosted
  • Local/Dev — Docker Compose, no AWS needed.
  • Staging/Learning — kind cluster + self-hosted prometheus.
  • Production — AMP (150-day retention, HA) + AMG (SSO).
  • Cost at your scale — AMP ~$15/mo vs Datadog ~$400/mo.
  • Scrape locally always — in-cluster Prometheus scrapes, remote_write to AMP.

Upgrade MetricsMiddleware for production metrics

First, upgrade your existing common/middleware.py. This adds p95-compatible histogram buckets, explicit error counters, and the slot label your dashboards need.

banking-services/common/middleware.py — full replacementpython
# Drop-in replacement for your existing middleware.py
# Key upgrades:
#  1. Explicit histogram buckets tuned for fintech SLOs
#  2. Separate http_errors_total counter (4xx + 5xx split)
#  3. In-flight gauge (saturation signal)
#  4. slot + version labels from env vars (injected by Docker Compose / Helm)
#  5. Path normalisation: /accounts/uuid → /accounts/{id} (prevents cardinality explosion)

from fastapi import Request
from starlette.middleware.base import BaseHTTPMiddleware
from prometheus_client import Counter, Histogram, Gauge, Info
import time, os, re

# ── Latency buckets aligned to fintech SLOs ──────────────────────────────────
# <50ms = fast, <200ms = good, <500ms = acceptable, >500ms = SLO risk
# These are what histogram_quantile(0.95, ...) uses for p95 calculation
LATENCY_BUCKETS = (
    0.010, 0.025, 0.050, 0.100, 0.200,
    0.500, 1.0, 2.5, 5.0, 10.0
)

SKIP_PATHS = {"/metrics", "/health", "/healthz", "/ready", "/favicon.ico"}
UUID_PATTERN = re.compile(r'/[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}')
NUM_PATTERN   = re.compile(r'/\d+')


class MetricsMiddleware(BaseHTTPMiddleware):
    def __init__(self, app, app_name: str):
        super().__init__(app)
        self.app_name = app_name
        slot    = os.getenv("SLOT", "local")     # blue | green | local
        version = os.getenv("APP_VERSION", "dev")

        # ── Counters ─────────────────────────────────────────────────────────
        self.req_total = Counter(
            'http_requests_total', 'Total HTTP requests',
            ['service', 'method', 'endpoint', 'status', 'status_class', 'slot']
        )
        self.err_total = Counter(
            'http_errors_total', 'HTTP 4xx and 5xx errors',
            ['service', 'method', 'endpoint', 'status', 'error_class', 'slot']
        )
        # ── Latency histogram ─────────────────────────────────────────────────
        self.latency = Histogram(
            'http_request_duration_seconds', 'HTTP request duration',
            ['service', 'method', 'endpoint', 'slot'],
            buckets=LATENCY_BUCKETS
        )
        # ── Gauges ───────────────────────────────────────────────────────────
        self.in_flight = Gauge(
            'http_requests_in_flight', 'Current in-flight requests', ['service', 'slot']
        )
        self.service_up = Gauge('up', 'Service up status', ['app', 'slot'])
        # ── Business KPI counter ──────────────────────────────────────────────
        self.biz_ops = Counter(
            'business_operations_total', 'Business operation counts',
            ['service', 'operation', 'status', 'slot']
        )
        # ── Service info ──────────────────────────────────────────────────────
        self.svc_info = Info('service_build', 'Service metadata')

        self.slot = slot
        self.service_up.labels(app=app_name, slot=slot).set(1)
        self.svc_info.info({'service': app_name, 'slot': slot, 'version': version})

    async def dispatch(self, request: Request, call_next):
        if request.url.path in SKIP_PATHS:
            return await call_next(request)

        endpoint = self._norm(request.url.path)
        self.in_flight.labels(service=self.app_name, slot=self.slot).inc()
        start = time.perf_counter()

        try:
            response = await call_next(request)
            dur = time.perf_counter() - start
            status = response.status_code
            cls = f"{status // 100}xx"

            self.req_total.labels(
                service=self.app_name, method=request.method,
                endpoint=endpoint, status=status, status_class=cls, slot=self.slot
            ).inc()

            if status >= 400:
                ec = "client_error" if status < 500 else "server_error"
                self.err_total.labels(
                    service=self.app_name, method=request.method,
                    endpoint=endpoint, status=status, error_class=ec, slot=self.slot
                ).inc()

            self.latency.labels(
                service=self.app_name, method=request.method,
                endpoint=endpoint, slot=self.slot
            ).observe(dur)

            self._biz(request.url.path, request.method, status)
            return response

        except Exception as e:
            self.service_up.labels(app=self.app_name, slot=self.slot).set(0)
            raise
        finally:
            self.in_flight.labels(service=self.app_name, slot=self.slot).dec()

    def _norm(self, path: str) -> str:
        path = UUID_PATTERN.sub('/{id}', path)
        path = NUM_PATTERN.sub('/{id}', path)
        return path

    def _biz(self, path: str, method: str, status: int):
        ops = {
            ("/accounts", "POST"): "account_creation",
            ("/token", "POST"): "authentication",
            ("/transactions", "POST"): "transaction",
        }
        op = ops.get((path, method))
        if op:
            self.biz_ops.labels(
                service=self.app_name, operation=op,
                status="success" if status < 400 else "failure",
                slot=self.slot
            ).inc()

Alert rules for local practice

observability/prometheus/rules/fintech-alerts.ymlyaml
groups:
  - name: fintech.errors
    rules:
      - alert: HighErrorRate
        expr: |
          sum by (service, slot) (rate(http_errors_total{error_class="server_error"}[5m]))
          /
          sum by (service, slot) (rate(http_requests_total[5m])) > 0.02
        for: 2m
        labels: {severity: critical}
        annotations:
          summary: "{{ $labels.service }} error rate {{ $value | humanizePercentage }}"

      - alert: High4xxRate
        expr: |
          sum by (service, slot) (rate(http_errors_total{error_class="client_error"}[5m]))
          /
          sum by (service, slot) (rate(http_requests_total[5m])) > 0.10
        for: 5m
        labels: {severity: warning}
        annotations:
          summary: "{{ $labels.service }} 4xx rate elevated"

  - name: fintech.latency
    rules:
      - alert: HighP95Latency
        expr: |
          histogram_quantile(0.95,
            sum by (service, slot, le) (rate(http_request_duration_seconds_bucket[5m]))
          ) > 0.300
        for: 5m
        labels: {severity: critical}
        annotations:
          summary: "p95 latency SLO breach — {{ $labels.service }} ({{ $value | humanizeDuration }})"

  - name: fintech.health
    rules:
      - alert: ServiceDown
        expr: up{job=~"account-service|auth-service|transaction-service"} == 0
        for: 1m
        labels: {severity: critical}
        annotations:
          summary: "Service DOWN: {{ $labels.job }}"

      - alert: DeadMansSwitch
        expr: vector(1)
        labels: {severity: none}
        annotations:
          summary: "Prometheus is alive and scraping"

  - name: fintech.business
    rules:
      - alert: AuthFailureSpike
        expr: |
          rate(business_operations_total{operation="authentication",status="failure"}[5m]) > 5
        for: 3m
        labels: {severity: warning}
        annotations:
          summary: "High auth failure rate — possible brute force"

      - alert: TransactionSuccessRateLow
        expr: |
          rate(business_operations_total{operation="transaction",status="success"}[5m])
          /
          rate(business_operations_total{operation="transaction"}[5m]) < 0.995
        for: 5m
        labels: {severity: critical}
        annotations:
          summary: "Transaction success rate below 99.5%"

Phase 2

Real Kubernetes on your Mac with kind

kind (Kubernetes IN Docker) creates a real, multi-node Kubernetes cluster locally. This is the closest you can get to EKS without an AWS bill. Same Helm charts, same kubectl commands.

Why kind over minikube? kind supports multi-node clusters (needed to simulate blue/green on separate nodes), integrates better with Docker, and is what most CI pipelines use for K8s testing. minikube works too — commands are largely identical, substitute minikube start for kind create cluster.

      expr: |
        sum by (service, slot) (rate(http_requests_total[5m]))

    - record: job:http_5xx_errors:rate5m
      expr: |
        sum by (service, slot) (
          rate(http_errors_total{error_class="server_error"}[5m])
        )

    - record: job:http_4xx_errors:rate5m
      expr: |
        sum by (service, slot) (
          rate(http_errors_total{error_class="client_error"}[5m])
        )

    - record: job:http_error_ratio:rate5m
      expr: |
        job:http_5xx_errors:rate5m / (job:http_requests:rate5m > 0)

  - name: fintech.latency
    interval: 15s
    rules:
    - record: job:http_request_duration_p50:5m
      expr: |
        histogram_quantile(0.50,
          sum by (service, slot, le) (rate(http_request_duration_seconds_bucket[5m]))

Step 3

Create IRSA role — Prometheus → AMP write permission

IRSA (IAM Roles for Service Accounts) lets your Kubernetes pods assume an AWS IAM role without static credentials. This is how Prometheus gets permission to write to AMP.

Terminal — create IAM role for Prometheus (pure AWS CLI)bash
# ── 1. Create the trust policy document ──────────────────────────────────────
cat > /tmp/prometheus-trust-policy.json << EOF
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "Federated": "arn:aws:iam::${ACCOUNT_ID}:oidc-provider/${OIDC_HOST}"
      },
      "Action": "sts:AssumeRoleWithWebIdentity",
      "Condition": {
        "StringEquals": {
          "${OIDC_HOST}:sub": "system:serviceaccount:monitoring:prometheus-kube-prometheus-prometheus",
          "${OIDC_HOST}:aud": "sts.amazonaws.com"
        }
      }
    }
  ]
}
EOF

cat /tmp/prometheus-trust-policy.json  # verify before creating

# ── 2. Create the IAM role ───────────────────────────────────────────────────
ROLE_ARN=$(aws iam create-role \
  --role-name fintech-prometheus-amp-write \
  --assume-role-policy-document file:///tmp/prometheus-trust-policy.json \
  --description "IRSA role for Prometheus to write to AMP" \
  --query Role.Arn \
  --output text)

echo "Role ARN: $ROLE_ARN"

# ── 3. Attach the AWS managed AMP policy ────────────────────────────────────
aws iam attach-role-policy \
  --role-name fintech-prometheus-amp-write \
  --policy-arn arn:aws:iam::aws:policy/AmazonPrometheusRemoteWriteAccess

# ── 4. Add additional permissions (query + rules) ────────────────────────────
cat > /tmp/prometheus-amp-policy.json << EOF
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "aps:RemoteWrite",
        "aps:QueryMetrics",
        "aps:GetSeries",
        "aps:GetLabels",
        "aps:GetMetricMetadata"
      ],
      "Resource": "arn:aws:aps:${REGION}:${ACCOUNT_ID}:workspace/${AMP_WORKSPACE}"
    }
  ]
}
EOF

aws iam put-role-policy \
  --role-name fintech-prometheus-amp-write \
  --policy-name amp-scoped-access \
  --policy-document file:///tmp/prometheus-amp-policy.json

# ── 5. Verify the role ───────────────────────────────────────────────────────
aws iam get-role --role-name fintech-prometheus-amp-write --query Role.Arn
aws iam list-attached-role-policies --role-name fintech-prometheus-amp-write
